## Authorization Overview

### Linux

bwssh supports two authorization modes on Linux:

1. **Disabled (default)**: All signing requests from local processes are allowed without prompts. This is suitable for personal workstations.

2. **Polkit-enabled**: Each signing request triggers a desktop prompt asking you to approve. Useful for shared machines or extra security.

### macOS

On macOS, authorization relies on Unix socket permissions. The agent socket is
created with mode `0600`, so only processes running as your user can connect.
There is no polkit equivalent — the `require_polkit` config option is ignored
on macOS (a warning is logged if set to `true`).

## Default Mode (No Prompts)

By default, bwssh allows all signing requests from local processes. This means:

- Any program running as your user can request signatures
- SSH connections "just work" without popups
- Protection comes from Bitwarden vault being locked when you're away

This is the recommended mode for most users on personal machines.

## Polkit Authorization (Advanced)

::alert{type="warning"}
Polkit integration requires system-level setup and may not work on all systems. Most users should use the default mode.
::

### What is polkit?

Polkit is Linux's authorization framework. When enabled, bwssh will show a desktop popup asking you to approve each signing request.

::alert{type="info"}
Due to polkit limitations, the popup shows a generic message rather than key/process details. The details are logged to the daemon journal instead (`journalctl --user -u bwssh-agent`).
::

### Requirements

Polkit integration requires:

1. A polkit authentication agent running (most desktop environments have one)
2. The bwssh policy file installed system-wide
3. The `require_polkit = true` config option

### Setup Instructions

**Step 1: Install the polkit policy**

```bash
# View the policy file
bwssh install --polkit

# Install it (requires sudo)
# Most distros (Fedora, Ubuntu, Arch):
bwssh install --polkit | sudo tee /usr/share/polkit-1/actions/io.github.reidond.bwssh.policy > /dev/null

# Older systems (if /usr/share path doesn't exist):
# bwssh install --polkit | sudo tee /etc/polkit-1/actions/io.github.reidond.bwssh.policy > /dev/null
```

**Step 2: Enable polkit in config**

Edit `~/.config/bwssh/config.toml`:

```toml
[auth]
require_polkit = true
```

**Step 3: Restart the daemon**

```bash
bwssh stop && bwssh start
```

**Step 4: Verify**

```bash
bwssh status
# Should show: Polkit: enabled
```

### Troubleshooting

If `bwssh status` shows `Polkit: failed`:

1. **Check D-Bus is running**: `echo $DBUS_SESSION_BUS_ADDRESS`
2. **Check polkit agent**: Your desktop should have a polkit agent (GNOME, KDE, etc. include one)
3. **Check policy file**: `ls /etc/polkit-1/actions/io.github.reidond.bwssh.policy`

If polkit doesn't work on your system, set `require_polkit = false` (the default) to allow signing without prompts.

## Approval Caching Modes

When polkit is enabled, you can control how often prompts appear:

| Mode             | Behavior                                         |
| ---------------- | ------------------------------------------------ |
| `always`         | Prompt for every sign request                    |
| `per_connection` | Prompt once per SSH connection                   |
| `ttl`            | Prompt once per key+program, cache for N seconds |

Configure in `~/.config/bwssh/config.toml`:

```toml
[auth]
approval_mode = "per_connection"  # or "always" or "ttl"
approval_ttl_seconds = 300        # for "ttl" mode
```

## Forwarded Agent Protection

When you SSH into a remote server with agent forwarding (`ssh -A`), programs on that server can request signatures from your agent. This is a security risk.

bwssh protects against this by default:

```toml
[auth]
deny_forwarded_by_default = true  # Block forwarded requests
```

With this setting, only local programs can use your SSH keys. Remote servers with agent forwarding will be denied.

To allow forwarded requests (not recommended):

```toml
[auth]
deny_forwarded_by_default = false
```
